# Resonant Spectra → Unreal Engine

Virtual light rigs grown from the PHishy Art album. Every photograph becomes a
lighting plot — beams where its bright lights are, aimed the way its light
streaks; washes in its region colours; a plume column at its warm centre — and
the whole album becomes a performance in a dark, fogged hall.

Three layers, each usable without the next:

| Layer | What it is | Needs |
| --- | --- | --- |
| `rigs/*.json` | One lighting plot per photo, in Unreal units. Generated by `npm run export:rigs`. | Node (already required by the repo) |
| `build_stage.py` | Editor Python. Builds the hall, fog, camera, every rig, and a Level Sequence that performs the album on a timer. | UE 5.5+, Python Editor Script Plugin (on by default) |
| `Plugins/ResonantSpectra/` | C++ plugin. Live conductor: analyses whatever the game is playing and drives the rigs from the music, exactly like the web app. | A C++ project + Visual Studio Build Tools |

**What has and hasn't been verified.** The exporter has been run against all 56
photos here. `build_stage.py` has been syntax-checked and executed end to end
against the real rig data with a stand-in for the `unreal` module — so the
logic is sound, but the actual engine calls run for the first time on your
machine. The C++ has been reviewed but not compiled (no engine here). If
anything in step 2 or 3 fails, paste the Output Log — every line the script
prints starts with `[rs]`.

## 1 · Generate the rigs

```bash
npm install
npm run export:rigs
```

Writes `unreal/rigs/photo_NNN.json` and `unreal/rigs/index.json`. The rigs
committed in this repo are already current; re-run after the album changes.

### The stage frame

Centimetres, Unreal axes: **X forward** (into the stage), **Y right**, **Z up**.

```
                 back wall / photo plane   X = 800
   ┌────────────────────────────────────────────┐  Z = 900 ceiling
   │  ▪ beams hang at X=620, Z per photo         │
   │  ▪ washes face the wall from X=640          │
   │  ▪ photo projected: Y −1100..1100, Z 860..120 │
   │  ▪ plume column on the floor at X=420       │
   │                                              │
   │                      camera  X=−1150  Z=260  │
   └────────────────────────────────────────────┘  Z = 0 floor
                Y = −1200 ◄──────────────► Y = 1200
```

A photo's `(u, v)` — `u` left→right, `v` top→bottom — maps to `(Y, Z)` on the
back wall. Beam directions are the photo's streak direction in that plane,
leaned 45° toward the camera so the shafts read in the fog. Cone angle comes
from how directional the light is in the picture (`aniso`): a sharp streak is
an 8° beam, a soft glow a 20° one.

### One rig, abridged

```json
{
  "name": "photo_001", "energy": 1.0, "smearAngleDeg": 89,
  "palette": ["#0d0df9", "#330db5", "…"],
  "fog": { "density": 0.062, "albedo": [160,130,246], "scatteringDistribution": 0.7 },
  "beams": [{ "id": 0, "location": [620,-330,670], "direction": [-0.41,0.11,-0.9],
              "color": [241,119,129], "intensityCd": 8534, "outerConeDeg": 17.5,
              "volumetricScattering": 2.2, "ignite": 0.20 }],
  "washes": [{ "location": [640,-825,798], "color": [10,10,80], "intensity": 200, "size": [300,220] }],
  "plume":  { "location": [420,-76,40], "color": [167,29,253] }
}
```

`ignite` is the tension at which that beam comes on — beam 0 at 0.20, beam 1
at 0.34, and so on — the same staggered ignition the web app uses, so the rig
climbs with the jam instead of switching on all at once.

## 2 · Build the stage (Editor Python)

Open your project in UE 5.5+. Then either:

- **Window ▸ Output Log**, switch the command prompt from *Cmd* to *Python*, and run
  ```
  py "C:/Users/joeca/code/art-experiment/unreal/build_stage.py"
  ```
- or **Edit ▸ Execute Python Script…** and pick the file.

It creates `/Game/ResonantSpectra/Maps/RS_Stage`, builds everything, saves,
and logs a summary. Expect it to take a minute or two: 56 photos × ~20
lights, plus a 1,000-track sequence. Then **Play**.

Knobs at the top of the file:

| Setting | Default | Notes |
| --- | --- | --- |
| `MAX_RIGS` | `None` (all) | Set to `4` while iterating — builds in seconds. |
| `BUILD_PHOTO_PLANE` | `True` | Imports each photo and puts it on the back wall, faintly emissive, so the beams *reveal* it. Turn off for lights only. |
| `MOVEMENT_SECONDS` | `24` | Seconds per photo in the timed performance. |
| `CREATE_NEW_LEVEL` | `True` | `False` builds into the currently open level instead. |

What it makes, in the Outliner under **ResonantSpectra/**:

- **Hall/** — floor, walls, ceiling in near-black; a truss; `Fog`
  (Exponential Height Fog, volumetric on, density and albedo from photo 1);
  `Post` (bloom up, manual exposure, light vignette); `Camera` (Cine Camera,
  22 mm, aimed at the wall centre); `Performance` (Level Sequence Actor,
  auto-play, loop).
- **Rigs/photo_NNN/** — `_BeamN` Spot Lights, `_WashN` Rect Lights,
  `_Plume0-2` Point Lights, and `Photo_photo_NNN` (the plane). Everything
  Movable, and tagged: `rs_stage`, `rs_beam|rs_wash|rs_plume|rs_photo`,
  `rig:photo_NNN`, `ignite:0.20`, `base:8534`. The tags are the contract the
  C++ driver reads — don't strip them.
- **`RS_Performance`** Level Sequence — each photo is a movement following the
  web app's no-music curve (build → peak → release): washes fade in and
  breathe, beams ignite in sequence and flash on release, the plume column
  surges around the peak, the photo's glow rises and falls, and the camera
  pushes in ~2.6 m over the full 22-minute run.

Re-running the script removes everything it built last time (by tag) first.

If the photo plane comes in rotated or mirrored, it's the Plane mesh's UV
orientation versus the pitch I used — adjust the `rot(90, 0, 0)` in
`build_photo_plane` (try `rot(90, 180, 0)` or `rot(-90, 0, 0)`). It doesn't
affect the lights.

## 3 · Live music (C++ plugin)

Copy `unreal/Plugins/ResonantSpectra/` into your project's `Plugins/` folder
(create it if needed). The project must be a C++ project — if it isn't yet,
**Tools ▸ New C++ Class…** once will convert it. Re-open the project; accept
the prompt to rebuild. Then re-run `build_stage.py` (or just drop an
`ResonantRigDriver` actor into the level) — the script places one automatically
when the class exists.

From then on, **Play** does this:

- `UResonantConductorComponent` starts spectral analysis on the **master
  submix** (everything the game plays) and each tick computes
  `Bass / Mid / Treb`, a normalised `Tension`, a decaying `Flash`, and fires
  `OnRelease` when a peak collapses — the exact logic of the web app's
  `computeConductor()`, including the auto-gain that makes it relative to the
  track's own dynamics and the fix that resets the hold clock when audio
  begins.
- `AResonantRigDriver` stops the Level Sequence, groups the tagged lights into
  rigs, and applies the conductor every tick with the web app's light
  formulas. Releases cross-fade to the next rig. With no audio it falls back to
  the same timed movement, so the stage always performs.

Both are Blueprint-friendly: the driver exposes `NextRig`, `PrevRig`,
`GoToRig`, `CurrentRig`; the conductor exposes every value and the
`OnRelease` event, so you can hang anything else off the music.

**Getting music into it.** The conductor hears what *Unreal* plays, not what
Windows plays. Easiest: drop an **Ambient Sound** actor in the level with a
`SoundWave` (auto-activate on), or drive a **Media Player**. To react to
Spotify / a browser / the web app itself, add the **Audio Capture** plugin, an
`AudioCapture` component pointed at a loopback device (VB-Cable or "Stereo
Mix"), and route it to a submix you assign to the conductor's `Submix`.

## Where this could go

- **Real fixtures.** The rig JSON is a lighting plot. Unreal's **DMX plugin**
  can drive actual moving heads over Art-Net/sACN from the same conductor —
  the beams' pan/tilt come straight from each photo's streak directions.
- **Niagara plumes.** The plume column is three point lights standing in for
  an emitter. A Niagara system spawned at `plume.location`, coloured
  `plume.color`, with spawn rate bound to the conductor's `Bass × Tension²`,
  is the faithful version of the web app's rising plumes.
- **nDisplay / LED wall.** The photo plane is already the Reveal look. On a
  real LED wall behind real fixtures it becomes the thing the web app is a
  sketch of.
